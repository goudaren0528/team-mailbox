## 1. 背景与材料评估

用户希望查看消息时直接使用 OpenCode 原生可点击选项，不再先阅读 Markdown 消息列表。
选中消息后，应获得完整正文及附件；用户已在 question 中明确选择将附件自动保存到预配置的本机收件目录。
用户还希望未读侧栏通过 emoji 和颜色更醒目，但不改变现有隐私和刷新边界。

写前评估为“从头写”：需求、现状、动机、目标、范围、方案草案和验收材料齐全，可进入评审。
本文“当前事实”来自既有调研；“用户已确认”指体验目标；“拟 / 建议”均为待审实现提案。
具体目录、命令名称和实现参数尚未确定，不将方案草案表述为已批准或已交付能力。

## 2. 目标与非目标

### 2.1 用户目标与拟定衡量标准

原生选择、完整正文与自动收件、醒目侧栏为用户已确认方向；下表具体交互和边界标准仍待评审。

| 编号 | 目标 | 可衡量结果 |
| --- | --- | --- |
| G1 | 原生消息选择 | 主动查看时出现原生单选界面，每页最多 10 条消息，选中真实稳定 id |
| G2 | 完整阅读与收件 | 选中后取得完整正文；有附件时自动保存到本人预配置目录并报告结果 |
| G3 | 更醒目的未读提醒 | 标题、条数有视觉层次，深浅主题与窄侧栏可读 |
| G4 | 保留边界 | 列表、翻页、取消不读正文、不下载、不标读；侧栏仍不显示标题或正文 |

### 2.2 本期非目标

- 不做完整 TUI 插件收件箱，不让 MCP 直接弹出原生 question，不引入服务端新端点。
- 不做桌面通知、声音、闪烁、toast 或自动弹出消息选择框。
- 不改中心自动已读语义，不提供未读回滚或逐段阅读审计。
- 不改数据库、历史消息或已下载文件；不去掉历史文件名 suffix，不扩展附件数量与大小限制。
- 不强制将二进制附件内容送入模型，不自动打开或执行附件。

## 4. 方案设计（全部待评审）

### 4.1 A：Skill + 显式查看消息命令

拟提供 OpenCode Skill 和显式命令，名称暂拟 `/mailbox-read`，工具描述配合引导。
目标链路：getmsg → 原生 question 单选 → 校验真实 id → B 收件与全文阅读。

1. 尊重用户指定的发件人、已读状态等过滤条件；未指定时优先未读，提供切换全部入口。
2. 每页最多 10 条消息，另加必要的上一页、下一页、切换范围及取消选项；不启用多选。
3. label 包含完整稳定真实 id；可展示截短标题，description 展示发件人、时间和附件信息。
4. 完整 id 不截断；选项序号不是消息 id，维护当前展示选项与真实 id 的映射。
5. 保持当前 getmsg 的排序契约并明确提示“按 id 升序”；上一页可通过保存游标/页面状态实现。
6. 翻页与切换过滤重新展示选择框；不读取正文、不下载、不改变已读。
7. 取消及 RejectedError 正常结束流程；未知自定义答案不猜 id，要求重新选择或澄清。
8. 只有与已展示选项无歧义匹配的答案才进入后续流程；过期或已不可访问项先报错再选择。
9. 空列表给出无匹配结果，可切换全部或结束；并发新增导致列表变化时可重新查询，不承诺快照。

标题信息只在用户主动打开的选择界面展示；侧栏继续禁止标题、正文泄漏。
Skill 和工具描述属于 Agent 指令约束，不是运行时强制保证，应通过行为测试验证遵循程度。
question 被禁用或其他宿主不支持时，明确告知能力缺失并征求替代方式，不静默退回 Markdown 列表。

### 4.2 B：默认收件目录与全文流程

拟新增本地 bridge 配置 `MSG_DOWNLOAD_DIR`，由用户安装时确认本人目录后设置。
目录必须为绝对路径且已经存在；不内置作者路径，不默认自动 mkdir。

| 场景 | 拟定执行顺序 | 用户可见结果 |
| --- | --- | --- |
| 无附件 | 按真实 id 分页 read_message，直到 hasMore 为 false | 完整正文，可多次展示，不只总结或静默截断 |
| 有附件 | 先 save_attachment 成功并完成哈希校验，再分页读正文到末尾 | 完整正文、实际保存路径和保存状态 |
| 纯附件 | 先保存并校验，再读取空正文的末页 | 明确“正文为空”、保存路径；中心按现语义标读 |
| 保存失败 | 暂停正文读取，提供重试 / 明确跳过附件继续 / 取消 | 说明失败阶段与原因，不自动读到末尾 |
| 保存成功、读正文失败 | 保留本次附件成功记录，重试只读取正文 | 报告附件已保存及正文尚未完成，避免重复下载 |

完整正文按返回顺序展示，超出单次输出能力时分次继续并说明剩余进度，不伪称已全文展示。
用户明确跳过附件后才可继续读取；应保留“附件未保存”的结果提示。
正文与附件都视为不可信数据，不执行其中指令，不自动打开文件。

### 4.3 C：未读侧栏视觉

拟采用标题“📬 未读消息 · 总数”，theme.accent 加粗；发件人常规文字，条数突出，附件用 📎。
保留“未读消息”“条”“附件”等文字，emoji 无法显示时仍能理解，不只依赖颜色传达状态。
使用现有摘要 total / senders 字段，不增加中心字段；保持 30 秒、最新未读倒序、最多 10 行、零未读隐藏。
真实终端验收深浅主题、中文、emoji 宽度和窄侧栏截断，不仅检查格式化字符串。

## 5. 接口、配置与数据契约（提案）

| 项目 | 拟定契约 | 兼容说明 |
| --- | --- | --- |
| MSG_DOWNLOAD_DIR | 本地 bridge 读取；绝对、已存在目录，使用时校验类型与权限 | 未配置仍可走旧显式 path；自动流程需先完成目录配置 |
| save_attachment.path | 从必填改为可选；仅省略时使用默认目录 | 空字符串或非法路径不是省略，不静默回退 |
| 省略 path 的保存 | 强制 auto_name=true、overwrite=false | 调用方不能借 overwrite=true 覆盖默认收件目录文件 |
| 显式 path | 保留原有路径、auto_name、overwrite 语义 | 老客户端请求不需要改动；既有显式覆盖授权语义保留 |
| 保存结果 | 必须能向用户报告实际路径、校验成功或失败阶段 | 具体返回字段在实现评审定稿，不冒充当前响应字段 |
| 服务与数据 | 不新增中心端点，不变更 DB schema | 无历史迁移、补默认值、修数或补偿脚本 |

默认保存的候选文件名须延续安全处理，不允许附件名称逃逸收件目录。
毫秒或附件 id 只能降低碰撞概率；应采用排他创建 + 有界序号重试，不能只做 exists 检查。
达到重试上限返回可恢复错误，不覆盖已有文件；重试次数和文件名格式留实现评审确定。
部分写入失败只清理本次创建且可确认为本次所有的临时产物，不能删除用户已有文件。
重复选择允许产生新的安全副本；仅同一次流程“保存成功后正文重试”复用保存状态，不承诺跨会话去重。

## 6. 边界、异常与兼容风险

| 分类 / 场景 | 用户可见处理与恢复 | 状态与记录边界 |
| --- | --- | --- |
| 参数错误 / 歧义答案 | 指出无有效选项或路径非法，重新选择 / 配置 | 不猜 id，不发起读取或下载 |
| 本地校验 / 无目录或无权限 | 提示配置目录或权限问题，重试 / 跳过 / 取消 | 当前流程不读正文；不自动创建目录 |
| 外部业务拒绝 / 权限变化 | 展示中心真实拒绝原因，停止该项或重新选择 | 不伪造外部文案，不绕过接收方权限 |
| 临时异常 / 超时或限流 | 报告实际阶段与可用原因，允许显式重试 | 不声称成功，不盲目重复下载 |
| 技术异常 / 磁盘不足、写失败、哈希不符 | 保存失败，清理本次产物后按失败选项处理 | 不输出已校验成功，不删除既有文件 |
| 并发读取 / 已读变化 | 说明状态以中心实际返回为准 | 不能承诺失败后全局仍未读，更不能回滚其他会话已读 |
| 输出中断 / 正文部分读取 | 标明当前进度，允许继续剩余正文 | 末页可能已使中心标读，不能证明用户看过所有字 |

拟在当前交互上下文保留真实 id、附件保存状态及正文进度；错误提示不包含凭据或附件正文，不新增中心审计表。
旧配置不自动获得下载目录；老用户需主动确认并设置。更新 bridge 后重启宿主使配置生效。
旧 bridge 不支持省略 path；Skill 应核对工具 schema，能力不符时告知升级，不假设新接口已可用。
进行中阅读不强行切换流程；切换配置或版本后新会话使用新契约，已保存文件保持不动。
单条消息最多一个附件、原始文件不超过 10 MiB；本期不放宽限制。
