# Local duty v1 intake compatibility

This local, receive-side parser accepts `on-duty.work.v1` WORK messages only. It does not modify the ordinary dispatch Skill or its sending contract. Mailbox sender and target project must be supplied from the trusted store grant, not taken from a requester self-report; parsing a valid message does not authorize execution. Git commit existence/type and any eventual file access must be independently verified.

The title and body must agree on ticket, role, mode and project. Unlike the original parser, the title's human-readable summary need not be byte-for-byte equal to the body's nonempty `summary`, matching the dispatch contract. Known optional fields include `code.base_omission_reason`, `environment.profile` and `environment.account_ref`, `references.message_ids`, `previous_report_id`, and a known-bug `bug` on TEST_FIX. Unknown properties at any WORK object layer are rejected. References to Issue/PR, notes, priorities, budgets, limitations or logs can be expressed in the approved document/references format or explanatory prose; this v1 parser does not introduce undocumented free-form object keys.

Local safety narrowing: `code.related_files` accepts only repository-relative paths without absolute/drive/UNC roots, empty or dot segments, parent (`..`) segments even after backslash separator normalization, or control characters. This is lexical validation **not symlink protection**; execution must resolve and check real paths inside the repository. `constraints.allow_commit` and `constraints.allow_push` may be `false` or omitted but `true` is rejected at intake: this local duty v1 does not grant commit/push authority, regardless of the ordinary dispatch protocol's ability to describe such authorization.
