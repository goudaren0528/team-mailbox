## 1. 背景

team-mailbox 是团队内网的 Agent 信箱，成员通过各自的 MCP bridge 收发文本和文件，中心服务保存消息。当前已部署，登记成员 4 人，已支持文本与 ≤10 MiB 文件传输。

**当前现象**：系统是纯拉取模型，没有任何通知。成员不主动调用 `getmsg` 就不知道有新消息，实际使用中出现过发送方发完、接收方长时间未察觉的情况。

**已确认的技术结论**（见调研）：

- MCP 服务端可以主动发送通知，但 OpenCode 收到 MCP 日志通知后**只写入内部日志，不展示给用户**（`packages/opencode/src/mcp/index.ts` 中处理为 `Effect.logInfo`）。因此「服务端推送即弹窗」不可行。
- OpenCode TUI 右侧区域代码中名为 **Sidebar**，其内容由插件 slot 渲染。内置的 Context、MCP、Todo、Modified Files 均通过 `api.slots.register` 注册 `sidebar_content` 实现。
- **该 slot 接口未出现在 OpenCode 官方插件文档中，仅存在于源码**，属于非承诺稳定接口。
- `POST /tui/show-toast` 是官方文档记载的接口，但 toast 会自动消失，不适合承载「待办清单」语义。

**为何现在做**：消息送达后无人察觉，削弱了工具的实际价值；侧栏常驻展示能在不打断工作的前提下让人看到待办。

## 2. 目标

### 2.1 核心目标

|目标|衡量标准|
|---|---|
|未读消息在 OpenCode 侧栏常驻可见|有未读时侧栏显示发件人、条数、附件数；无未读时该区块不占位|
|读完正文即自动标记已读|调用 `read_message` 且读到正文末尾后，该消息 `read` 变为 true，下一次刷新侧栏不再显示|
|提醒失效不影响核心功能|OpenCode 接口变更或插件异常时，侧栏静默降级，消息收发与 `getmsg` 完全不受影响|
|同事可自助安装|README 提供可直接转发的安装提示词，同事的 Agent 据此完成 MCP 与插件配置|

### 2.2 非目标（本次不做）

- 桌面系统通知、声音提醒、跨应用弹窗。
- 实时推送（仍为定时拉取，不建立长连接）。
- 侧栏内直接阅读正文、回复、下载附件等交互操作。
- 为其他客户端（Claude Code、Codex、Cursor）提供等价插件。
- 已读状态的撤销（无「标记为未读」能力）。
- 消息免打扰、静音、按人过滤等偏好设置。

## 3. 现状分析

### 3.1 当前业务链路

```Plain Text
发送方 Agent → 中心服务 → SQLite 保存
接收方：需主动说「查看未读消息」→ Agent 调 getmsg → 才知道有消息
        （不主动问就完全无感知）
```

### 3.2 当前已读机制

```Plain Text
getmsg        → 列出摘要，不改已读状态
read_message  → 返回正文，不改已读状态（server.js:247 注释明确「Does NOT mark as read automatically」）
mark_read     → 唯一改变已读状态的入口，需显式调用
```

数据层：`messages.read_at` 为 NULL 表示未读；已建索引 `idx_messages_to_unread(to_name, read_at, id)`。

### 3.3 关键问题或现状限制

|编号|问题/限制|简单说明|业务影响|目标结果|
|---|---|---|---|---|
|P1|无任何到达提醒|纯拉取，无推送无展示|消息长时间无人查看|侧栏常驻显示未读概况|
|P2|已读需额外一步|读完正文仍要显式 `mark_read`|Agent 常遗漏，已读状态长期不准|读完正文自动标记已读|
|P3|已读不准导致提醒失真|未读堆积|侧栏会长期显示早已看过的消息|已读准确后侧栏自动清空|
|P4|无查询未读概况的轻量接口|只能拉完整列表|侧栏高频刷新代价大|新增轻量汇总接口|

### 3.4 目标业务结果

```Plain Text
利浩文发来 2 条消息（含 1 个附件）
  → 30 秒内，洪伟填的 OpenCode 侧栏出现：
      📬 未读消息
        利浩文  2 条 · 1 附件
  → 洪伟填："看看利浩文发来的消息"
  → Agent 调 getmsg 列出 → read_message 读正文
  → 读完即自动已读，下次刷新侧栏该条目消失
```

## 4. 方案设计

### 4.1 服务端：轻量未读汇总接口

|编号|改进项|方案|影响范围|
|---|---|---|---|
|S1|新增 `GET /api/unread-summary`|返回当前成员按发件人聚合的未读统计，不含正文与标题|`src/server.js`、`src/db.js`|
|S2|响应结构|`{total, attachments, senders:[{name, count, attachments, latestTime}], updatedAt}`，`senders` 按最新消息时间倒序|同上|
|S3|查询实现|单条 SQL 聚合，复用既有 `idx_messages_to_unread` 索引|`src/db.js`|
|S4|权限一致|身份仍由来源 IP 判定，仅返回当前成员收件箱统计|无新增权限模型|

### 4.2 服务端：读完正文即已读

|编号|改进项|方案|影响范围|
|---|---|---|---|
|R1|`read_message` 自动标记|当本次请求读到正文末尾（`hasMore === false`）时，标记该消息已读|`src/server.js` 读取分支|
|R2|分段读取语义|分段读取中间页不标记，只有读到末尾才标记，避免只读开头就被清除|同上|
|R3|响应字段|响应 `read` 反映**本次操作后**的状态，并新增 `markedRead`（布尔）说明本次是否由该调用触发|同上|
|R4|`mark_read` 保留|仍可显式批量标记，用于用户明确说「这些不用看了」的场景|无改动|
|R5|空正文消息|纯附件消息（text 为空串）读取时同样视为读到末尾，标记已读|同上|

### 4.3 MCP 工具

|编号|改进项|方案|
|---|---|---|
|T1|新增 `get_unread_summary({})`|返回未读汇总，供 Agent 或插件查询；描述注明这是概况而非正文|
|T2|`read_message` 描述更新|明确说明「读到正文末尾会自动标记已读」，不再宣称不自动已读|
|T3|工具总数|由 8 个增至 9 个|

### 4.4 OpenCode 侧栏插件

|编号|改进项|方案|
|---|---|---|
|U1|插件形态|TUI 插件，注册 `sidebar_content` slot，随仓库提供于 `integrations/opencode/`|
|U2|数据来源|直接 HTTP 调用中心的 `GET /api/unread-summary`，不经 MCP（插件与 MCP bridge 是两个进程）|
|U3|配置|读取环境变量 `MSG_SERVER_URL`；未配置时插件不渲染任何内容|
|U4|刷新频率|默认 30 秒轮询，可由 `MSG_UNREAD_POLL_MS` 覆盖，最低 10 秒|
|U5|显示格式|标题 `未读消息`，每行 `<发件人>  <N> 条 · <M> 附件`；无附件时省略附件段|
|U6|空状态|`total === 0` 时不渲染任何内容，不占用侧栏空间|
|U7|失败降级|请求失败、超时、返回异常一律静默跳过本轮，保留上一次成功结果；连续失败不抛异常、不阻塞 OpenCode。**不额外标注「陈旧」**：第 10 章 C2 已确定侧栏只显示发件人、条数、附件数，不引入第四类信息|
|U8|接口失效防护|slot 注册包裹在 try/catch 中，注册失败仅记录日志，不影响 OpenCode 启动|

### 4.5 README 与安装说明

|编号|改进项|方案|
|---|---|---|
|D1|安装提示词|README 增加可直接转发的段落，覆盖 clone、`npm ci`、MCP 配置、插件安装、doctor 验证|
|D2|插件为可选项|明确说明不装插件不影响收发，只是没有未读提醒|
|D3|稳定性声明|注明侧栏 slot 是 OpenCode 源码级接口、非官方承诺，升级后可能失效及应对方式|
|D4|中英双语|README 与 README.zh-CN 同步|

## 5. 接口与数据契约

### 5.1 `GET /api/unread-summary`

无请求参数，身份由来源 IP 判定。

```json
{
  "total": 3,
  "attachments": 1,
  "senders": [
    { "name": "利浩文", "count": 2, "attachments": 1, "latestTime": "2026-09-21T08:12:00.000Z" },
    { "name": "陈袤楠", "count": 1, "attachments": 0, "latestTime": "2026-09-21T07:40:00.000Z" }
  ],
  "updatedAt": "2026-09-21T08:15:00.000Z"
}
```

不含消息正文、标题、项目标签和消息 id：侧栏只做概况提示，避免把内容暴露在常驻界面上。

### 5.2 `read_message` 响应变更

新增 `markedRead` 字段；`read` 语义变为「本次操作完成后的已读状态」。

```json
{ "id": 7, "read": true, "markedRead": true, "hasMore": false, "text": "..." }
```

分段读取中间页：`read: false, markedRead: false, hasMore: true`。

### 5.3 错误分类

|分类|示例|用户提示|处理方式|
|---|---|---|---|
|来源不可识别|插件所在机器 IP 未映射|插件静默不显示|不重试风暴，按轮询间隔重试|
|中心不可达|服务未启动、网络不通|侧栏保留上次结果并标注陈旧|静默降级|
|响应格式异常|字段缺失或类型不符|丢弃本轮结果|静默降级，记录本地日志|
|已读标记失败|`read_message` 主流程成功但标记失败|返回正文，`markedRead: false`|不因标记失败导致读取失败|

## 6. 技术约束与风险

### 6.1 向后兼容

- `get_unread_summary` 为新增工具，旧 bridge 不受影响。
- `read_message` 响应新增字段，旧调用方忽略即可；但**已读行为发生变化**，这是有意的破坏性变更，需在文档与提交信息中写明。
- 未升级的同事：`read_message` 仍不自动已读，需继续显式 `mark_read`；侧栏插件不可用。
- 数据库无 schema 变更，无需迁移。

### 6.2 技术约束

- 插件依赖 OpenCode 源码级 slot 接口，**官方文档未记载，升级可能失效**。
- 插件与 MCP bridge 是不同进程，无法共享连接，需各自访问中心。
- 轮询非实时，最坏情况延迟等于轮询间隔。
- 插件需安装在每位成员机器上，管理员安装不会让他人看到。
- 仅覆盖 OpenCode，其他客户端无此能力。

### 6.3 风险与依赖

|风险|影响|应对|
|---|---|---|
|OpenCode 升级改动 slot 接口|侧栏不再显示|注册与渲染均包裹异常保护；README 说明降级表现；核心收发不受影响|
|自动已读导致误判|用户只扫一眼就被标记已读|仅在读到正文末尾时标记；分段读取中途不标记|
|轮询增加中心负载|4 人 × 30 秒，约每分钟 8 次轻量查询|单条聚合 SQL，走既有索引；可通过环境变量调大间隔|
|插件泄露消息内容|常驻界面被他人瞥见|汇总接口不返回正文与标题，只显示发件人和数量|

## 10. 已确认决策（2026-09-21 洪伟填确认）

|编号|事项|决策|
|---|---|---|
|C1|轮询间隔|**默认 30 秒**，可由 `MSG_UNREAD_POLL_MS` 覆盖，最低 10 秒|
|C2|消息标题|**不显示**。侧栏只显示发件人、条数、附件数；也不额外标注哪条最新，靠倒序排列体现|
|C3|发件人过多|**不截断内容，但限制显示行数**：最多显示 10 行发件人，超出部分不再渲染，由用户自行读完后自然减少|

其余内容按本 PRD 第 4–9 章执行。
